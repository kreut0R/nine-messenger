# Nine: клиент для ПК

Прототип клиента на Kotlin и Compose Multiplatform. Сейчас собирается для ПК (Windows, macOS, Linux).
Android и iOS добавятся как новые цели в тот же модуль, общий код лежит в `commonMain`.

Сервера пока нет. Чаты и сообщения живут только на этом устройстве, никуда не отправляются и лежат
в зашифрованном виде (см. «Безопасность»). Протокол Signal для переписки между людьми подключим вместе с сервером.
Выдуманных контактов в приложении нет: список чатов пуст, пока вы не создадите свой.

## Что умеет

- создать чат (кнопка «+»), открыть его и отправить сообщение: Enter отправляет, Shift+Enter переносит строку;
- вкладки «Все», «Непрочитанные», «Архив», поиск по чатам, поиск по переписке;
- перенос чата в архив и обратно, выбор цвета своих сообщений;
- переписка сохраняется в зашифрованный файл и восстанавливается при следующем запуске;
- аккаунт создаётся на устройстве без телефона и почты, вход по коду доступа, копия ключа в отдельном файле.

## Как запустить

Нужен JDK 17 или новее. Gradle скачается сам.

```sh
cd client
./gradlew :composeApp:run        # запустить приложение
./gradlew :composeApp:desktopTest # запустить тесты
```

На Windows вместо `./gradlew` используйте `gradlew.bat`.

Где лежат данные: три файла в папке приложения.
Windows: `%APPDATA%\Nine`, macOS: `~/Library/Application Support/Nine`, Linux: `~/.local/share/nine`.
Чтобы начать с чистого листа, выберите в профиле «Выйти и стереть данные» или удалите папку.
Открытый `messenger.json` из прежних версий при создании аккаунта переносится внутрь и стирается.

## Как устроен код

Код разложен по слоям. Каждый знает только о тех, что ниже.

```
composeApp/src
├── commonMain/kotlin/app/nine
│   ├── domain/        модели (чат, сообщение) и источник времени, без зависимости от интерфейса
│   ├── data/          MessengerRepository: единственное место, где меняются чаты; MessengerStore: где они лежат
│   ├── security/      Vault: аккаунт, код доступа, копия ключа; Lockout: пауза после неудачных попыток
│   ├── presentation/  чистая логика экрана: фильтры, лента с днями и группами, форматы времени, состояние выбора
│   ├── ui/            Compose: theme, components, lock (вход), profile, chatlist, conversation, contact, dialog
│   ├── NineRoot.kt    самый верх: экран входа до открытия аккаунта, потом мессенджер
│   └── NineApp.kt     три колонки и окна создания чата и профиля
├── desktopMain        точка входа Main.kt, FileVault (шифрование, Argon2id, AES-GCM), окно выбора файла
├── commonTest         тесты логики, не требуют окна
└── desktopTest        тесты шифрованного хранилища и файлового (старого, открытого)
```

Когда появится сервер, отправка сообщения пройдёт через `MessengerRepository.sendMessage`:
сообщение сначала сохраняется со статусом `Delivery.Local`, затем уходит на сервер и меняет статус.
Интерфейс при этом не меняется: галочки у сообщений уже умеют показывать `Sent` и `Read`.

## Оформление

Тема одна, тёмная: чёрный фон, нейтральные панели с тонким светлым контуром, зелёный только на выбранном
чате, своих сообщениях и галочках. Градиентов нет. Шрифт Inter лежит в ресурсах (лицензия SIL OFL в `licenses/`).
Цвета и размеры текста собраны в `ui/theme`.

Настоящего размытия фона под стеклом в Compose Multiplatform пока нет, поэтому стекло передано контуром, бликом
на верхней кромке и полупрозрачными шапкой и полем ввода.

## Безопасность

Что сделано. Аккаунт — пара ключей Ed25519, созданная на устройстве. Ключ входа и вся переписка лежат в файлах
только в виде шифртекста (AES-256-GCM, у каждой записи свой случайный nonce). Главный ключ зашифрован ключом из кода
доступа (Argon2id, 64 МиБ, 3 прохода). Сам код нигде не хранится: верный код проверяется тем, что главный ключ
расшифровывается без ошибки. Своей криптографии нет, только AES-GCM из JDK и Argon2id и Ed25519 из BouncyCastle.

Файлы в папке данных: `vault.json` (зашифрованный главный ключ, настройки Argon2id, счётчик неудачных попыток),
`identity.enc` (ключ входа), `messenger.enc` (переписка).

Что это даёт и чего не даёт:

- Человек, получивший только выключенное устройство или копию папки, прочтёт переписку лишь подобрав код.
  Минимум восемь символов, лучше фраза из нескольких слов. Короткий цифровой PIN по копии файлов перебирается быстро,
  поэтому быстрый PIN появится позже, вместе с привязкой ключа к системному хранилищу (Keystore, Keychain, DPAPI).
- Пауза после пяти неудачных попыток (30 секунд, дальше вдвое дольше, не больше часа) останавливает подбор в самом
  приложении. Счётчик лежит в открытом `vault.json`, поэтому тот, у кого есть копия файлов, его обходит.
  Против такого подбора работает только стоимость Argon2id и длина кода.
- Стирание затирает файлы нулями и удаляет их. На SSD и в журналируемых файловых системах это не гарантия:
  надёжность даёт шифрование, а не затирание.
- Пока приложение открыто, ключи лежат в оперативной памяти. Кто контролирует работающий компьютер, видит всё,
  что видите вы. Автоблокировки по бездействию пока нет.
- Забытый код восстановить нельзя. Остаётся копия ключа (профиль → «Сохранить копию ключа») с отдельным паролем.
  Она возвращает аккаунт, но не переписку: переписка живёт только на устройстве.

Чего ещё нет: протокола Signal для переписки с другими людьми (нужен сервер), тревожного PIN, стирания после
неудачных попыток, автоблокировки, привязки к системному хранилищу ключей.
